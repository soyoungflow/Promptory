## 1. Django ↔ FastAPI 「분리 구조」를 보여주는 방법

평가는 「Django 안에서 AI를 직접 돌리지 않고, **별도 FastAPI 서버**가 있다」는 것을 **설명 + 근거 화면**으로 확인합니다.  
아래 **3가지만** 해도 충분하고, 발표 시간이 있으면 4~5번까지 하면 만점에 가깝습니다.

### 방법 A — URL이 다르다 (가장 쉬움, **라이브 필수**)

브라우저 탭을 **두 개** 열어 나란히 보여줍니다.

| 탭 | URL | 의미 |
|----|-----|------|
| Django | `http://13.211.8.186/` | 메인 UI + `/api/*` |
| FastAPI | `http://13.211.8.186/ai/docs` | **별도** AI 서버 Swagger |

**한 줄 멘트:**

> 사용자·API는 Django(8000)로 들어오고, AI 추론 API는 FastAPI(별도 컨테이너)가 담당합니다. nginx가 `/`와 `/ai/`로 나눠 줍니다.

**캡처 파일명 예:** `01-django-home.png`, `02-fastapi-swagger.png`

---

### 방법 B — `docker compose ps` (컨테이너 분리, **라이브 또는 스크린샷**)

EC2 SSH 후:

```bash
cd /home/ubuntu/Promptory
docker compose ps
```

**강조할 컨테이너:**

| 이름 | 역할 |
|------|------|
| `promptory-web-1` | Django + DRF + daphne |
| `promptory-ai_server-1` | FastAPI (mock/HF) |
| `promptory-celery_worker-1` | 비동기 → FastAPI 호출 |
| `promptory-redis-1` | Celery broker |
| `promptory-db-1` | PostgreSQL |

**한 줄 멘트:**

> web과 ai_server는 **이미지·프로세스·포트가 분리**된 컨테이너이고, Celery가 그 사이에서 FastAPI를 호출합니다.

**캡처 파일명 예:** `03-docker-compose-ps.png`

---

### 방법 C — DevTools Network (요청 경로, **라이브 필수**)

1. `http://13.211.8.186/blueprints/new/` 에서 **설계서 생성하기**
2. Chrome DevTools → **Network** 탭

**보여줄 요청 순서:**

```
POST /api/blueprints/design/     → 202 + task_id   (Django)
GET  /api/tasks/{task_id}/status/ → PENDING → SUCCESS (Django, 폴링)
GET  /api/blueprints/design/{id}/ → 설계 결과 JSON (Django)
```

**한 줄 멘트:**

> 브라우저는 Django API만 호출합니다. Celery Worker가 **내부 네트워크** `http://ai_server:8000/transform` 으로 FastAPI를 호출하고, 결과를 DB에 저장한 뒤 Django가 조회 API로 돌려줍니다.

(내부 호출은 DevTools에 안 보이므로, 슬라이드·`docker compose logs celery_worker`로 보완)

**캡처 파일명 예:** `04-devtools-design-202.png`, `05-devtools-task-success.png`

---

### 방법 D — FastAPI에서 직접 호출 (AI 서버 독립성, **라이브 30초**)

`http://13.211.8.186/ai/docs` → **POST `/transform`** (Try it out)

```json
{
  "prompt_text": "주간 마케팅 보고서를 자동으로 작성하는 업무",
  "max_steps": 4
}
```

응답에 `decomposed_steps`, `model_used: "mock"` 확인.

**한 줄 멘트:**

> Django 없이도 FastAPI만 단독으로 AI 변환 API가 동작합니다. 운영에서는 Celery가 같은 엔드포인트를 호출합니다.

**캡처 파일명 예:** `06-fastapi-transform-response.png`

---

### 방법 E — Prometheus targets (스크랩 분리, **스크린샷 OK**)

`http://13.211.8.186/prometheus/targets`

| job | target | 의미 |
|-----|--------|------|
| `django` | `web:8000/metrics` | Django 메트릭 |
| `fastapi` | `ai_server:8000/metrics` | FastAPI 메트릭 |

**캡처 파일명 예:** `07-prometheus-targets-up.png`

---

### 분리 구조 설명용 슬라이드 (말로만, 화면 불필요)

`docs/NGINX_REVERSE_PROXY.md` mermaid 다이어그램을 슬라이드 1장에 넣어 두면, 라이브 시연 전 30초 설명에 충분합니다.

```
브라우저 → nginx:80 → / → web (Django)
                    → /ai/ → ai_server (FastAPI)
Celery worker ──(내부)──→ ai_server:8000
```

## 2. 라이브 시연 vs 스크린샷·영상 — 정리표

| # | 보여줄 내용 | 방식 | 필수도 | 비고 |
|---|-------------|------|--------|------|
| **L1** | EC2 메인 접속 `http://13.211.8.186/` | **라이브** | ★★★ | 실행 불가 시 -10 감점 |
| **L2** | 로그인 → 설계서 만들기 → 결과 표시 | **라이브** | ★★★ | 핵심 AI E2E |
| **L3** | Task 상태 변화 (스피너 → 완료) | **라이브** | ★★★ | 비동기 시연 |
| **L4** | 보관함 → **내 설계서** 탭 | **라이브** | ★★☆ | DB 저장·조회 |
| **L5** | FastAPI `/ai/docs` 탭 열기 | **라이브** | ★★★ | 서버 분리 증명 |
| **L6** | `/ai/docs`에서 POST `/transform` 1회 | **라이브** | ★★☆ | 30초면 충분 |
| **L7** | DevTools Network (design 202, task status) | **라이브** | ★★☆ | Django→비동기 흐름 |
| **S1** | `docker compose ps` (8서비스) | 스크린샷 | ★★☆ | SSH 캡처 또는 미리 촬영 |
| **S2** | Prometheus targets UP | 스크린샷 | ★★☆ | L8 시간 없으면 S2만 |
| **S3** | Grafana **Promptory Phase 4** 대시보드 | 스크린샷 | ★★☆ | No data면 변환 1회 후 촬영 |
| **S4** | Django Admin — Task / AgentTransformation 행 | 스크린샷 | ★☆☆ | 말로 대체 가능 |
| **S5** | GitHub Actions CD 성공 로그 | 스크린샷 | ★☆☆ | 배포 5점·가산점 |
| **S6** | Celery worker 로그 (`transform_success`) | 스크린샷 | ★☆☆ | L3 보완 |
| **V1** | HF 로컬 추론 (Qwen 등) | **영상 30~60초** | ★☆☆ | EC2 mock 발표와 병행 |
| **V2** | 전체 시연 리허설 (3~5분) | 영상 백업 | ★☆☆ | 네트워크 장애 대비 |

**기호:** ★★★ = 발표에서 반드시 라이브 / ★★☆ = 라이브 권장, 스크린샷으로 대체 가능 / ★☆☆ = 있으면 좋음

## 5. EC2 vs 로컬 역할 (발표 멘트용)

| 환경 | 역할 | 시연 방식 |
|------|------|-----------|
| **EC2** (`LLM_PROVIDER=mock`) | 발표 **본선** — UI, Celery, FastAPI mock, 배포, 모니터링 | **라이브** |
| **로컬** (`LLM_PROVIDER=huggingface`) | HF 실모델 연동 **증빙** | **영상·스크린샷** |

**표준 멘트:**

> 발표 시연은 EC2에서 mock FastAPI로 안정적으로 E2E를 보여 드리고, Hugging Face 실모델은 동일 아키텍처로 로컬에서 검증했습니다. `LLM_PROVIDER` 환경변수만 바꾸면 전환됩니다.
